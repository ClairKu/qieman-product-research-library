核心目的：推品原则：定制方案优先，标准策略兜底供给底座：研究院品类矩阵 四笔钱 + 严选双体系升级AI产品工厂模式落地

0设计输入与命题拆解

先把本次改版的输入条件与设计命题摆到一张桌面上，所有方案都必须回答这些命题。

业务输入

  • 品类矩阵升级：研究院提供新品类体系（品类表待接入），四笔钱与严选策略体系同步升级，将有新重点策略上线，需要配套产品页面与陪伴体系。
  • 推品是核心目的：页面的第一KPI是推品转化（签约/跟投），不是浏览时长。
  • 推品优先级铁律：所有推品逻辑优先推定制方案，再推标准策略。
  • 现有资产：规划（四笔钱规划/定制方案/养老规划）、工具（温度计、每日估值、行情信号、指数估值、自建自助、额度宝）、专区（养老、全球）、策略货架。

设计命题（每个方案必须回答）

  1. 定位命题：这个页面是「工具+货架」还是「服务门户」？用户为什么每周回来？
  2. 分发命题：怎么让四类用户（跟推荐/按目标/按持仓/自主DIY）各自高效找到适合的方案？主次如何取舍？
  3. 呈现命题：策略不只是列表——如何用风险×收益二维视图（基于组合风险分数）让用户「看见」货架全貌？
  4. 生产方式命题：页面如何支持AI产品工厂——运营弹性编排、用户自选布局、服务组件化？

品类矩阵是「货」的坐标系：每只策略都应有品类标签（资产类别×地域×策略风格×风险档），这是货架可视化、AI推荐、运营编排的共同数据前提。建议将「品类打标」列为改版P0数据工程。

1.2 推品总漏斗：一条主路 + 三条辅路

进入投顾页：状态识别（新客 / 有持仓 / 有目标 / 高活跃）千人千面的分流依据
主路：规划引导 → 定制方案（四笔钱规划 / 养老规划 / AI小顾定制）推品第一优先级：先定制
辅路1：标准策略货架（四笔钱分桶 + 严选 + 专区）不愿走规划的用户直接选品
辅路2：持仓调优（诊断 → 调仓/补配建议 → 推品）存量用户的复购引擎
辅路3：自主DIY（工具 + 筛选 + 自建组合）留住专业用户，不是推品主战场

主次取舍（明确牺牲什么）

  • 首屏只留一个主行动：未完成规划者首屏主推「做规划→出定制方案」；已有定制方案者首屏主推「方案执行/调优」。标准货架永远在第二屏起。
  • 工具降级为“钩子”：温度计、每日估值等工具不再平铺一级入口，而是收进「市场工具条」，其价值是高频回访钩子＋向推品场景导流（如温度低→估值机会→对应品类策略）。
  • DIY收纳到货架尾部：自建自助、全量筛选收进「自己选」入口，服务专业用户但不占首屏。

方案A规划驱动的传统页升级 —— “一条漏斗做到底”

信息架构（固定五段式）

  1. 规划状态区（首屏主行动）：四笔钱规划进度 / 定制方案入口 / 养老规划，按用户状态切换文案与CTA。
  2. 官方主推位：当季1个重点定制方案 + 1个重点标准策略，运营手动排期。
  3. 市场工具条：温度计、每日估值、行情信号、指数估值、额度宝收纳为一行图标 + 异动红点。
  4. 货架区：四笔钱分桶Tab（活钱/稳钱/长钱/养老/全球）+ 严选策略列表 + 风险收益全景图入口。
  5. 自己选：筛选器、自建自助组合、全部策略。

维度评估

适用判断适合作为兜底/降级形态或极限工期下的过渡版

方案B工具+货架的编排式产品页 —— “运营可配的千人千面卡片流”

核心机制：插槽 + 组件注册表 + 编排规则

  • 页面 = 插槽序列（slot-1..n），每个插槽由「编排引擎」按 人群 × 档期 × 行为 决定渲染哪个组件。
  • 组件注册表：规划卡、状态诊断卡、官方主推卡、工具卡、货架卡（按品类矩阵渲染）、专区卡、陪伴卡、全景图卡……每个组件有统一契约（数据接口 + 埋点 + 降级态）。
  • 运营后台：新策略上线＝配置一张「主推卡」+ 挂载货架桶位，不需要发版；档期化运营（严选升级周、养老月）。

评估

维度评估
推品效率高：主行动随用户状态切换，定制优先规则内置于编排引擎（规则可审计，合规友好）
运营弹性高：策略上线、专区档期均后台配置；具备A/B实验位
研发成本中：需要组件契约、编排引擎、运营后台三件套；可复用现有卡片体系逐步迁移
AI产品工厂契合中高：组件化是AI工厂的前置条件，编排规则未来可由AI生成
风险编排规则需合规审查（投顾建议适当性）；千人千面需埋点与人群平台支撑
合规注意：按持仓/测评结果差异化推品属于投顾建议范畴，编排规则需留痕、可回溯，且与用户风险测评结果做适当性校验。

方案CAI驱动的可组装服务页 —— “AI产品工厂的门店”

三层结构

  1. AI层（常驻）：顶部AI小顾入口 + 「AI今日看板」组件——把行情、持仓、规划缺口合成为一句今日建议（内容经合规审核链路），是页面的“每天回来的理由”。
  2. 官方组件层：官方推荐的服务组件集（我的方案、严选货架、全景图、专区、陪伴流），默认布局由运营/AI编排，逻辑同方案B。
  3. 用户组装层：用户可添加/移除/排序可选组件（估值表、额度宝、行情信号、攒钱计划、自建组合看板…），形成个人化投顾工作台；官方保留1-2个不可移除的合规与主推位。

生产方式变革（AI产品工厂落地点）

  • 服务组件 = 数据契约 + 卡片模板 + 行动点（复用已验证的微信AI原子组件PRD范式，见 docs/02）。
  • 新策略上线流程：研究院出品类与策略 → AI按组件模板自动生成产品页/陪伴内容初稿 → 合规审核 → 运营一键挂载。页面成为服务组件的分发容器，而非一次性开发的界面。
  • 同一套组件可同时分发到：APP投顾页 / 微信小程序AI对话流 / 企微陪伴消息，一次生产多端复用。

评估

维度评估
推品效率潜力最高（AI结合上下文的主动推品），但依赖AI建议质量与信任建立，短期不确定性大
运营弹性最高：组件市场 + AI编排；运营从“配页面”升级为“管组件供给”
研发成本高：组件框架、用户布局系统、AI编排与合规链路；需分阶段
AI产品工厂契合强：即是AI产品工厂的产品形态本身
风险AI输出合规（需智审类审核前置）；用户自选布局可能弱化官方推品位——用锁定槽位解决；老年/低频用户认知成本

关键设计细节

  • 以组合风险分数为唯一横轴锚点（口径统一、监管可解释），风险五档（低/中低/中/中高/高）作为色带分段背景，兼容用户已有认知。
  • 指标切换白名单：年化收益、最大回撤、波动率、夏普，均为已有MCP口径，避免自造指标；默认年化收益+悬浮展示回撤。
  • 推品埋点位：点击任一策略点 → 策略半屏卡（含“看是否适合我”按钮→定制流程），保证可视化服务于推品而非纯浏览。
  • 数据前提：全量货架策略需补齐风险分数与品类标签（本次演示17只中1只缺失，全量覆盖率待数据盘点）。
