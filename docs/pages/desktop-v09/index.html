一句话主张

  • 把投顾页从「静态货架清单」升级为 「推品操作系统」：一条主线（定制优先的推品决策流）× 一张地图（品类矩阵驱动的风险-收益可视化货架）× 一套组件（可编排、可运营、可个性化的服务组件）。
  • 推荐路线不是三选一，而是 B为货架内核、C为页面框架、A为过渡骨架 的三阶段融合：先用A的结构承接新策略上线，同步把B做成严选/四笔钱的新货架形态，最终沉淀为C的组件化千人千面页面。
① 背景与目标

为什么是现在

  • 策略供给侧升级：研究院品类矩阵迭代，新重点策略筹备中——新四笔钱 + 新严选体系将上线，需要产品页面、陪伴体系等承接。
  • 商业模式拐点：2025.11起投顾费成为直接收入，推品效率=收入效率。
  • 唯一未升级的一级页面：投顾页仍是多年前的静态货架结构，与AI小顾、同路人权益、养老专区等新能力脱节。
  • 生产方式升级契机：借本项目落地AI产品工厂模式，改变「策划→开发→上线」的页面生产方式。

改版目标（建议的北极星与护栏）

  • 北极星：投顾页→签约投顾资产的转化效率（页面UV→方案采纳→签约AUM）。
  • 辅助目标：定制方案渗透率、四笔钱人均配置笔数、选品决策时长下降（客服咨询占比下降）。
  • 护栏（不可破坏）：且慢的「简单感」与信任感——96%盈利占比、772天持有时长是买方投顾人设的资产；改版加能力，不加噪音，不做排行榜、不做爆款导购。
② 核心设计逻辑（所有方案的公共底座）

2.1 一条推品主线：定制优先的决策流

任何入口进来，先识别用户任务，优先导向定制方案；定制不成，按品类矩阵推标准策略；再不成，给工具让用户自助。每一层都是推品，只是自动化程度不同。
用户带着什么来？（四类任务识别：新钱要投 / 有目标要规划 / 有持仓要调优 / 想自己找品）
↓
第一优先：定制方案（AI小顾秒级方案 / 顾问定制 / 四笔钱规划书）——「先给我一笔钱和一个期限，我给你一套方案」
↓ 用户不愿给信息 / 金额期限不适配
第二优先：标准策略（新四笔钱旗舰 + 严选货架，按品类矩阵与风险分匹配露出）
↓ 用户想自己挑
第三层：工具与DIY（配置地图筛选 / 估值信号 / 自建组合 + 诊断回流：DIY结果可一键「让且慢帮我看看」回到定制）

2.2 页面公式

投顾页 = ①规划引导层（识别任务，导流定制） + ②官方推荐层（千人千面推品位） + ③品类货架层（四笔钱×严选，地图+列表双形态） + ④专区层（养老/全球/攒钱统一框架） + ⑤工具层（估值/信号/自建，全部带回流推品钩子）。三个方案的差异只在这五层的「形态」与「生产方式」，主线与分层不变——这保证方案可以渐进演化而不推倒重来。

2.3 品类矩阵 → 货架的映射（占位，待品类文档解锁后精化）

以研究院品类为「行」（资产/策略品类），以四笔钱为「列」（资金用途），每个格子= 1个旗舰策略 + N个严选备选。页面不再是「四笔钱一列清单 + 严选另一列清单」的两张平行货架，而是一张矩阵：四笔钱是用户视角的入口，品类是研究院视角的库存，严选是每个格子里的深度。现况盘点已发现风险分20-50断档与短稳区同质化，新策略体系应优先填格。

③ 方案A 「结构进化版」——传统页面的最优解
A
结构进化版 成本低2-3个月可上线兜底方案
定位：不改变页面范式，把「五层结构」在现有技术栈上重排，保证新策略体系按时上线有承接。
① 规划引导条：「你有一笔什么钱？」金额+期限两个输入 → 直接出四笔钱归属与推荐（定制方案入口前置为交互，不再是banner）
② 官方推荐位：本期主推（运营配置 + 规则化千人千面：新客见旗舰/持仓客见补配/养老人群见专区）
③ 四笔钱×严选融合货架：四笔钱Tab保留，每Tab内=1旗舰置顶+品类分组的严选列表（合并m4/more，消灭二级「更多」页）
④ 专区通道：养老/全球/攒钱统一卡片规格
⑤ 工具区：估值/信号/自建（带推品钩子）
⑥ 陪伴信任区：96%盈利/772天/同路人权益/主理人内容流

关键改动

  • 定制方案从banner改为两问交互条（金额+期限），转化路径缩短为一步。
  • 严选货架并入四笔钱Tab，按品类矩阵分组，每组给「品类一句话」（解决同质化不可分辨）。
  • 产品卡升级：增加风险分徽章 + 回撤/波动微图 + 「适合谁」标签。
  • 工具区每个工具出口带「由此去配置」钩子（估值低估→对应品类策略）。

局限

  • 个性化靠规则位，天花板低；页面仍是硬编码，运营弹性有限。
  • 没有解决「可视化选品」；本质是更好的清单。
④ 方案B 「配置地图版」——风险-收益可视化货架（含可交互原型）
B
配置地图版 差异化最强可视化选品可嵌入A/C
定位：把「28个策略的列表」变成「一张可滑动探索的风险-收益地图」，以组合风险分数（晨星式1-100）为主轴，回答你提出的「不只是列表」。

交互设计（四个动作）

动作交互推品含义
滑风险滑杆从低到高滑动，地图高亮该风险带的策略，下方同步出「本档位推荐」卡（旗舰优先）用「我能承受多少」代替「哪个收益高」作为第一问，天然合规且符合买方立场

叠登录后叠加「我的持仓」落点与「我的风险测评带」——持仓偏离推荐带即出「调优建议」持仓调优推品的入口，接组合诊断能力（MCP已有）
点点策略气泡→速览卡（品类/主理人/费率/适合谁）→详情/定投缩短决策链

  • 对低金融素养用户有学习成本 → 不作为唯一形态，与列表双形态并存，默认视图按客群实验。
⑤ 方案C 「AI服务工厂版」——组件化编排的千人千面页面
C

定位：页面不再是「设计稿」，而是「组件库 × 编排规则 × 用户偏好」的运行时产物——落地你提出的AI产品工厂模式。

局限与依赖

  • 需要前端组件运行时 + 编排后台 + 审核流三块基建，首期投入最大；建议以「先内部编排（运营千人千面）、后用户自定义」分两步。

⑧ 推荐路线：三阶段融合（B为内核，C为框架，A为骨架）
Phase 1 · 承接新策略上线（~3个月）
方案A结构落地：规划引导条+矩阵化货架+专区/工具统一规格；方案B以「配置地图」组件嵌入严选区（先只读版：滑+切，不做持仓叠加）；新四笔钱/严选策略按品类矩阵进场。
验证：地图使用率、引导条→定制转化、货架CTR结构变化。
Phase 2 · 组件化改造（+3个月）
把Phase1的所有区块按方案C协议封装为组件；上线编排后台，运营开始人群×场景编排（新客/持仓客/养老/高净值四套默认编排）；地图升级持仓叠加与调优推品；AI辅助生成组件变体进审核流。
验证：编排迭代周期（周级→日级）、分人群转化差。
Phase 3 · 千人千面与自定义（+3个月）
开放用户自定义布局（可选组件添加/移除/排序）；推荐位从规则升级为模型排序；方案D在新客/DIY人群灰度（对话生成编排）。
验证：自定义留存提升、北极星（页面→签约AUM）全量归因。
关键依赖：①品类矩阵文档（映射表输入）；②内部埋点数据（分层与默认编排依据）；③风险分数据管线产品化（本次MCP已验证数据可得性）；④合规对指标呈现的评审前置到Phase1。

事项页面侧动作备注
