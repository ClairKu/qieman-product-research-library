盈米 AI 开放平台已经证明“金融能力有人需要”。下一阶段不再以接口数量为中心， 而是把能力变成可治理、可分发、可复用、可收费的持续服务。

核心判断：规模证明已经通过；2026 下半年的胜负手，是用增长、供货、变现三条主线， 打通“能力 → 服务 → 渠道 → 用户结果 → 收费”的经营闭环。

00 · Executive answer

一句话结论：平台已过“有没有需求”，现在要回答“能不能持续经营”

管理问题：今天最应该继续加码什么，最需要避免什么？

MAIN CONCLUSION OAP 已建立能力与需求的双边基础，但“活跃—复用—收费”仍未形成统一经营链。

9,145,099 次累计调用、8,292 名累计申请和 1,694 月活，证明市场有需求； WorkBuddy、百炼、SkillHub 等入口打开分发机会。下一步的组织重点，应从“继续做更多能力” 转向“把高价值能力做成服务、在渠道上重复使用，并用统一口径验证转化与收入”。

RECOMMENDED MOVE 以 WorkBuddy 做分发样板，以 AI 实验室做服务工厂，以双轨收费做商业验证。

所有新增项目必须回答：服务给谁、在哪用、如何复用、谁负责、用什么证据验收。

继续生态上架与高价值供给

把已有能力包装成可发现、可理解、可运行的专家 / Agent / Skills。

加码月活召回与持续使用

用户规模接近目标，但活跃与复用才决定平台是否真正成立。

停止以“完成接入”替代经营结果

接口打通、试用账号和一次调用都不能直接等同于用户价值或商业进展。

01 · Why & history

为什么做：让盈米专业能力进入下一代 AI 入口，并借开放生态寻找破圈点

起点不是“做一个技术平台”，而是提高金融服务生产效率，并解决 AI 小顾与且慢的用户破圈问题。

2025—2026进入大平台与商化

出现 C 端平台接入、首笔收入、阿里云合作和投标机会。

2026.04—06扩展 OpenClaw 与 Skills

04 · Review

问题回顾：我们不缺“能力存在”，缺的是把能力变成稳定结果的最后一公里

每个问题都必须对应一个经营损失和关闭条件，不能只停在系统现状描述。

01 · FRAGMENTATION中后台尚未完全打通

STARGATE 管 MCP，Skills / Agent 另有管理平台，供给、版本、权限、调用和经营数据难以统一追踪。

损失：资产无法统一经营
02 · QUALITYMCP / Skills 质量治理未闭环

需要目录、分层、Owner、评测、审批、审计、监控和上下架机制，而不是只确认“能调用”。

损失：规模放大风险
03 · RETENTION活跃与复用证据不足

累计申请和调用增长较快，但每周必用场景、次月留存、服务采纳与复访仍缺统一经营口径。

损失：增长不可持续
04 · MONETIZATION商化仍从方案走向闭环

SkillHub、百炼按量与 OAP C 端计费均有计划，但价格、免费额度、激励、支付和续费尚待跑通。

损失：价值无法被定价
05 · Operating model

统一经营模型：能力只是原料，持续服务才是平台可以增长与收费的商品

主链路必须同时拥有资产 Owner、质量门槛、渠道指标和商业结果。

SUPPLY能力供给

数据 / API / MCP / Skills，形成可用精品货架。

GOVERN质量治理

目录、Owner、评分、审批、监控与回滚。

CREATE服务创作

AI 实验室把意图编排成可运行服务。

DISTRIBUTE渠道分发

WorkBuddy、百炼、SkillHub、小顾与新入口。

REPEAT使用复用

首次完成、采纳、复访、订阅与留存。

MONETIZE收费承接

按量、套餐、服务包与机构解决方案。

06 · Three battles

下半年只抓三件事：增长、供货、变现；实验室是三者之间的连接器

每条主线都要有一个样板、一个数字和一个可复制机制。

GROWTH

增长：从申请用户转向持续使用

调用先过线，月活用召回打穿，申请用户靠生态上架和新入口托底。

  • 优先召回已有用户，建立“每周必用”场景
  • WorkBuddy 做首个渠道样板：上架 + 宣传 + 回流
  • 按来源追踪申请、首次完成、复访和付费
验收：月活 ≥2,000；申请 ≥10,000；次月留存进入周看板
SUPPLY

供货：保证有货可推、有货可卖

能力治理常态化，并把高价值能力包装成标准交付。

  • Q3 ≥25、年底 ≥30 个高价值 Skills
  • WorkBuddy 6 单专家 + 1 专家团，推进百炼 Agent
  • Quality Scorer + 交付模板成为上架门槛
验收：有 Owner、有评测、有版本、有渠道、有使用数据
MONETIZATION

变现：双轨验证收费闭环

外部平台按量 / 付费试点与 OAP C 端套餐并行，但免费额度不能破坏增长。

  • SkillHub 付费试点、百炼传统 MCP + One Key MCP
  • OAP 免费额度 + 分层计费 + 套餐 + 激励
  • Q4 至少复制到 2 个外部平台
验收：付费用户、收入、续费与单位服务成本可复算
07 · AI Lab

AI 实验室不是“再做一个站内工具”，而是金融 Agent 的创作、提审与分发系统

产品边界：协议可插拔，创作不被网页锁死，结果以专家 / Agent 形态回流平台。

01 · PLUG协议接入

支持 MCP / Skills 等标准协议；盈米精品能力做默认货架，第三方能力按权限与合规分级。

02 · CREATECLI / Agent 内创作

让创作者在 WorkBuddy、Cursor、Trae 等熟悉环境里直接创建服务。

03 · REVIEW打包与提审

服务必须带输入输出、依赖、评测、权限和版本，不能只交一段 Prompt。

04 · DISTRIBUTE回流货架

进入 WorkBuddy、应用广场、小顾等入口，形成发布、复用、订阅和付费闭环。

09 · Decisions

需要管理层拍板的不是“做不做”，而是主战场、责任人、收费与风险边界

若以下事项不冻结，团队会继续并行推进多个入口，但无法形成统一经营节奏。

DECISION 01将“月活与服务复用”设为 H2 第一经营优先级

累计申请和调用接近目标，不再让规模指标掩盖留存问题。

DECISION 02确认 WorkBuddy 为首个渠道样板，明确联合 Owner 与全矩阵宣传资源

目标是 Agent 上架、真实调用、来源回流和付费验证一起验收。

DECISION 03冻结 OAP C 端免费额度、套餐档位与激励原则

免费保规模，付费吃重度调用；避免价格策略与增长相互拆台。

DECISION 04冻结实验室第三方能力权限分级、CLI 首发平台与回流提审流程

先跑通 Batch 0，再扩大外部创作者；不以空白广场启动。

DECISION 05建立唯一资产账本与周经营看板

统一 Owner、版本、评测、权限、渠道、使用、收入与异常，关闭多后台碎片化。
